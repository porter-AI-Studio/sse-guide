RTCP 五軸插補系統：三層 SSE 架構實戰

前兩章我們學會了 SSE 的基礎推播與子行程整合。本章以一個真實的工業級系統 RTCP（Rotation Tool Center Point） 五軸 CNC 插補工具鏈為例，展示如何在「瀏覽器 → Node.js → C99 引擎」三層架構下，用 SSE 實現即時進度串流、批次確認控制、以及最終的 Plotly.js 結果視覺化。

ℹ️
本章目標
  • 理解三層系統的職責分工與溝通協定
  • 掌握 POST /run 如何同時充當觸發端點與 SSE 推播通道
  • 了解雙向 IPC：stdout 串流 + stdin 控制的設計模式
  • 看懂前端如何依照事件類型分別更新 UI 與送出控制指令

1. 三層關係圖

整個 RTCP 系統由三層組成，每層各有明確的職責，彼此透過兩條通道連接：

  • 第一層（瀏覽器）：所有使用者互動、G-code 解析、設定匯出、進度顯示、圖表渲染
  • 第二層（Node.js）：HTTP 閘道、子行程生命週期管理、SSE 推播橋接
  • 第三層（C99 引擎）：高效能數值運算，透過 CSV/JSON 輸入，以 IPC JSON 串流輸出

兩條通道的協定如下：

通道方向技術用途
瀏覽器 ↔ Node.js 雙向 HTTP POST + SSE EventSource 觸發運算、接收進度推播、送出控制指令
Node.js ↔ C99 引擎 雙向 child_process.spawn IPC stdout → JSON 進度串流；stdin ← continue / end

2. 系統架構與完整流程

以下循序圖展示從「使用者備妥輸入資料」到「結果視覺化」的完整互動流程，特別標注了 SSE 通道的建立時機與批次確認機制：

流程分為五個階段：

  1. 準備輸入資料：前端在瀏覽器本地完成 G-code 解析與機台設定，匯出 cl_input.csv 與 tatc_config.json。
  2. 建立 SSE 通道：前端對 POST /run 發送請求，伺服器回應 Content-Type: text/event-stream，此後同一個 HTTP 連線轉為推播通道。
  3. 子行程串流：Node.js 以 spawn() 啟動 rtcp_engine.exe --ipc，將 engine 的 stdout 逐行轉為 SSE 事件推播。
  4. 批次確認控制：Engine 每完成一批次（batch_end）便阻塞等待 stdin 輸入；瀏覽器透過 POST /control 回傳 continue 或 end。
  5. 任務完成：Engine 正常退出後，伺服器推播 exit 事件並關閉 SSE 連線，前端讀取 result.csv 進行視覺化。

3. 前後端主要功能方塊說明

3-1. 前端功能方塊（RTCP_UI / index.html）

前端是一個單頁四標籤的純 HTML 應用，不依賴前端框架，全部邏輯分散於四個 JS 模組：

模組 / 元件檔案職責
G-code 解析器 js/gcode_parser.js 解析 FANUC 五軸 G-code（G00/G01），擷取 X/Y/Z/A/C 路徑點，輸出結構化陣列
CSV 匯出器 js/csv_export.js 將路徑點陣列序列化為 cl_input.csv，以及將機台設定序列化為 tatc_config.json
前端插補預覽 js/interpolation.js 在瀏覽器端執行 JavaScript 版 SLERP 預覽，不需要呼叫伺服器即可快速確認結果
SSE 客戶端 + 控制面板 index.html（Tab 3） 對 POST /run 發起請求後轉為 SSE 接收端；偵測 batch_end 後顯示「繼續」按鈕；觸發 POST /control
結果視覺化 js/visualization.js 使用 Plotly.js 渲染七種圖表：資料表格、2D XY/XZ/YZ 軌跡、3D 彩色路徑、速度曲線

前端：SSE 接收與控制邏輯（關鍵片段）

// Tab 3 — 執行控制區塊
const progressEl = document.getElementById('progress');
const ctrlBtn    = document.getElementById('btn-control');
let   isBatchEnd = false;

async function runEngine() {
    // POST /run 回應的是 SSE 串流，需用 fetch + ReadableStream 處理
    const response = await fetch('/run', { method: 'POST' });
    const reader   = response.body.getReader();
    const decoder  = new TextDecoder();
    let   buf      = '';

    while (true) {
        const { done, value } = await reader.read();
        if (done) break;

        buf += decoder.decode(value, { stream: true });
        const lines = buf.split('\n');
        buf = lines.pop();

        for (const line of lines) {
            if (!line.startsWith('data: ')) continue;
            const evt = JSON.parse(line.slice(6));
            handleEvent(evt);
        }
    }
}

function handleEvent(evt) {
    if (evt.type === 'progress') {
        // 更新進度顯示
        progressEl.textContent = `t=${evt.t_ms} ms  s=${evt.s_mm} mm  rows=${evt.count}`;
    } else if (evt.type === 'batch_end') {
        // 批次完成：顯示繼續按鈕，等待使用者確認
        isBatchEnd = true;
        ctrlBtn.style.display = 'inline-block';
        ctrlBtn.textContent   = `繼續 (已完成 ${evt.count} 點)`;
    } else if (evt.type === 'exit') {
        progressEl.textContent = `✅ 完成，exit code=${evt.code}`;
        ctrlBtn.style.display  = 'none';
    }
}

// 送出控制指令：continue 或 end
async function sendControl(cmd) {
    await fetch('/control', {
        method:  'POST',
        headers: { 'Content-Type': 'application/json' },
        body:    JSON.stringify({ cmd })
    });
    isBatchEnd = false;
    ctrlBtn.style.display = 'none';
}

3-2. 後端功能方塊（Node.js server.js）

後端僅有一個 server.js，職責極為聚焦：充當前端與 C99 引擎之間的 IPC 橋接器。

端點方法職責
/run POST 防止重複啟動（409）→ 設定 SSE 標頭 → spawn 引擎 → stdout 逐行推播 → close 時 res.end()
/control POST 驗證引擎是否在執行 → 驗證指令為 continue/end → engine.stdin.write(cmd)
/（靜態） GET 提供 RTCP_UI 目錄下的 HTML/JS/CSS 靜態檔案

後端：子行程管理與 SSE 推播核心（完整 server.js）

'use strict';
const express = require('express');
const { spawn } = require('child_process');
const path = require('path');

const app = express();
app.use(express.json());
app.use(express.static(path.join(__dirname, 'RTCP_UI')));

const ENGINE_EXE = path.join(__dirname, 'RTCP_Engine', 'build', 'rtcp_engine.exe');
const ENGINE_CWD = path.join(__dirname, 'RTCP_Engine');

let engine = null;   // 確保同一時間只有一個執行中的引擎

/* ── POST /run — 啟動引擎並以 SSE 串流輸出 ──────────────────── */
app.post('/run', (req, res) => {
    if (engine) {
        return res.status(409).json({ error: 'Engine already running' });
    }

    // 宣告為 SSE 回應：這條 HTTP 連線從此轉為推播通道
    res.setHeader('Content-Type', 'text/event-stream');
    res.setHeader('Cache-Control', 'no-cache');
    res.setHeader('Connection', 'keep-alive');
    res.flushHeaders();

    engine = spawn(ENGINE_EXE, [
        '--input',  'data/cl_input.csv',
        '--config', 'data/tatc_config.json',
        '--method', 'slerp',
        '--dt',     '1',
        '--output', 'result.csv',
        '--ipc'           // IPC 模式：JSON 輸出到 stdout，並在 batch_end 後阻塞等待 stdin
    ], { cwd: ENGINE_CWD });

    let buf = '';

    // 攔截 stdout：逐行轉為 SSE data 事件
    engine.stdout.on('data', (chunk) => {
        buf += chunk.toString();
        const lines = buf.split('\n');
        buf = lines.pop();  // 保留未完整的最後一行
        for (const line of lines) {
            if (line.trim()) res.write(`data: ${line.trim()}\n\n`);
        }
    });

    engine.stderr.on('data', (chunk) => process.stderr.write(chunk));

    // 引擎結束：推播 exit 事件，關閉 SSE 連線
    engine.on('close', (code) => {
        if (buf.trim()) res.write(`data: ${buf.trim()}\n\n`);
        res.write(`data: ${JSON.stringify({ type: 'exit', code })}\n\n`);
        res.end();
        engine = null;
    });

    // 客戶端斷線：強制終止引擎
    req.on('close', () => {
        if (engine) { engine.kill(); engine = null; }
    });
});

/* ── POST /control — 透過 stdin 向引擎送出控制指令 ──────────── */
app.post('/control', (req, res) => {
    const { cmd } = req.body;
    if (!engine) return res.status(400).json({ error: 'No engine running' });
    if (cmd !== 'continue' && cmd !== 'end') {
        return res.status(400).json({ error: 'cmd must be "continue" or "end"' });
    }
    engine.stdin.write(cmd + '\n');
    res.json({ ok: true });
});

app.listen(3000, () => console.log('RTCP server: http://localhost:3000'));

3-3. C99 運算引擎（rtcp_engine.exe）

引擎以純 C99 撰寫，無任何第三方依賴，專注於數值計算。以 --ipc 旗標執行時進入 IPC 模式：

模組檔案職責
CLI 引數解析 main.c 解析 --input / --config / --method / --dt / --output / --ipc 等選項
CSV 讀入 csv_reader.c 從 cl_input.csv 載入路徑點（Xm, Ym, Zm, a_deg, c_deg, qw…qz, dt_ms）
JSON 設定載入 json_config.c 解析 tatc_config.json：Pivot 長度、A/C 軸方向與行程限制
四元數插補 interpolator.c / quaternion.c 支援四種插補法：Euler / SLERP / SQUAD / Quintic，1 kHz 輸出密度
TATC 逆向運動學 tatc_kinematics.c 將刀具中心點（CL）+ 姿態四元數轉換為機台座標（xm, ym, zm）及 A/C 軸角度
IPC 進度回呼 main.c（progress_cb） 每計算一點，以 JSON 格式輸出至 stdout；每批次後阻塞 stdin 等待 continue/end
CSV 寫出 csv_writer.c 輸出 14 欄結果：t_ms, Xcl, Ycl, Zcl, a_deg, c_deg, xm, ym, zm, s_mm, qw, qx, qy, qz

引擎 IPC 模式輸出格式（JSON Lines）

// 每個插補點完成後輸出：
{"type":"progress","t_ms":1.000,"s_mm":0.010,"count":1}
{"type":"progress","t_ms":2.000,"s_mm":0.020,"count":2}

// 每批次（預設 5 點）後輸出並阻塞，等待 stdin：
{"type":"batch_end","count":5}

// stdin 接收到 continue → 繼續；接收到 end → 提前退出
// 最終正常退出：Node.js 偵測到 close 事件，code=0

4. 快速啟動

確認 C99 引擎已編譯後，啟動 Node.js 伺服器：

# 1. 編譯 C99 引擎（需要 CMake + MSVC 或 gcc）
cd RTCP_Engine
cmake -B build
cmake --build build --config Release

# 2. 安裝 Node.js 依賴並啟動伺服器
cd ..
npm install
node server.js
# → RTCP server: http://localhost:3000

開啟瀏覽器進入 http://localhost:3000，依序操作四個標籤：

  1. Machine Config：填入機台幾何參數（Pivot 長度、A/C 軸行程）
  2. G-Code Input：上傳或貼上 FANUC 五軸 G-code 程式碼
  3. Export / Run：下載 CSV + JSON，點擊「Run Server」，即時觀察 SSE 進度串流與批次確認
  4. Visualize：上傳 result.csv，以 2D/3D 圖表驗證插補結果
💡
設計要點：POST 端點兼任 SSE 通道

本章最關鍵的 SSE 技巧是：POST /run 不是傳統的「回傳 JSON 的 REST 端點」，而是在接收 POST Body 後，立即切換為長連線的推播通道（flushHeaders()）。這個模式讓「觸發操作」與「接收推播」合而為一，省去額外的 GET SSE 端點，也讓 engine 的生命週期與前端的連線狀態嚴格綁定。

⚠️
單一引擎實例保護

伺服器以全域變數 engine 追蹤目前是否有引擎在執行。若重複觸發 POST /run，伺服器會回傳 409 Conflict，避免多個子行程同時競爭同一個輸出檔案。前端應在收到 exit 事件後才重新啟用「Run」按鈕。
