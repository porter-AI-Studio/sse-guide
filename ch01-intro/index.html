核心概念：什麼是 Node.js 與 SSE？

了解 Node.js 的事件驅動特性，以及 Server-Sent Events (SSE) 如何實現單向即時推播。

Node.js 簡介

Node.js 是一個基於 Chrome V8 引擎的 JavaScript 執行環境。它的最大特色是事件驅動 (Event-driven) 與非阻塞 I/O (Non-blocking I/O)，這使得它非常適合處理大量併發連線與即時資料傳輸的應用場景。

傳統的前端工程師若要跨足後端，Node.js 往往是最好的橋樑，因為可以使用熟悉的 JavaScript 語法來撰寫後端邏輯。不過，從前端走向後端，還需要補充 HTTP 協定、資料庫以及伺服器框架（例如 Express 或 NestJS）的知識。

Server-Sent Events (SSE) 技術詳解

Server-Sent Events (SSE) 是一種基於 HTTP 的伺服器推播技術。它允許伺服器將即時更新主動傳送給客戶端（通常是瀏覽器），而不需要客戶端不斷地發出請求。

💡

反轉傳統模式： 在傳統模式中，客戶端必須主動向伺服器要資料。而 SSE 反轉了這個模式，讓伺服器可以在資料準備好時，立刻「推播」給客戶端。

  sequenceDiagram
      participant C as 客戶端 (Browser)
      participant S as 伺服器 (Node.js)
      
      Note over C,S: 1. 傳統 HTTP 請求 (需不斷詢問)
      C->>S: GET /data (有新資料嗎？)
      S-->>C: 沒有
      C->>S: GET /data (有新資料嗎？)
      S-->>C: 有，給你資料
      
      Note over C,S: 2. SSE 單向推播 (連線一次，隨時接收)
      C->>S: GET /api/events (建立 SSE 連線)
      S-->>C: 200 OK (Content-Type: text/event-stream)
      S->>C: data: 第一筆資料
      S->>C: data: 第二筆資料

技術特點與優勢

  • 單向通信： 資料流只能從伺服器推播到客戶端，非常適合需要伺服器主動更新狀態的情境。
  • 基於標準 HTTP： 無需特殊的通訊協定，完全相容於現有的網路基礎設施。
  • 輕量高效： 相較於 WebSocket 更加輕巧，資源消耗較少。
  • 自動重連： 內建斷線自動重連機制。
  • 純文字傳輸： 設計用來傳輸 UTF-8 編碼的文字資料，非常適合傳送 JSON 或純文字。

SSE vs WebSocket vs Long Polling

特性 Server-Sent Events (SSE) WebSocket Long Polling (長輪詢)
通訊方向 單向 (伺服器 → 客戶端) 雙向全雙工 單向 (多次請求-回應循環)
基礎協定 HTTP WebSocket 協定 HTTP
自動重連 內建支援 需手動實作 需手動實作
適用場景 即時通知、資料流、打字機效果 聊天室、協作編輯、遊戲 相容性極度受限的舊環境

常見應用場景

  1. AI 聊天機器人： 例如 ChatGPT 的「打字機效果」，伺服器會將 LLM 產生的詞元 (Token) 透過 SSE 即時推播到前端。
  2. 即時資料監控： 金融市場的股票價格更新，或是伺服器資源（CPU、記憶體）的監控儀表板。
  3. 系統即時通知： 結合 Redis Pub/Sub，實作診所叫號、餐廳排隊等系統後端的推播架構。
